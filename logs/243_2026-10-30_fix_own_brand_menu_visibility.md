# Відображення власного виробництва й піци в меню

Причина: автоматична видимість вважала `/own-brand/*` звичайними інформаційними сторінками без статей. Піца наповнюється через окремий редактор, а інші напрями мають власний статичний контент; ці джерела не враховувалися у фільтрі.

У `lib/menu-content.ts` native-напрями з `content/own-brand.ts` і кореневий `/own-brand` додано до функціональних сторінок. Явний режим hidden збережено. У `app/public-site.css` desktop dropdown отримав max-height, overflow-y і overscroll-behavior для довгого списку. Два рівні та загальний ліміт 150 пунктів не змінювалися.

Під час перевірки знайдено актуальний `/app/content/own-brand-pizzas.json`, створений користувачем у файловій системі контейнера. Перед розгортанням app зупинено, актуальні дані скопійовано, підключено постійний `/srv/pchilka-app/data/app/content:/app/content` у production Compose. Після запуску підтверджено точний збіг файлу й відображення активної піци. Налаштування навігації не перезаписувалися.

Розгорнуто `pchilka-menu:20261030` (`97e81cf4e0cc`), healthy. Серверні копії та rollback: `/srv/pchilka-app/backups/menu-20261030-091554`; дані content потрібно зберігати підключеними і при відкаті коду.

Перевірки: `node scripts/check-site-menu.cjs` з регресією native-пунктів, явним hidden і 40 підпунктами; `tsc --noEmit --incremental false`; production build; публічний API меню містить піцу, всі шість дочірніх сторінок повертають 200; CSS містить прокрутку; health API 200; запасний банер не повернувся.

Окрема наявна перевірка `scripts/check-menu-content.cjs` зупиняється на рядку 41: стара фікстура `/loyalty/about` отримує 400 замість 200. Такий самий збій відтворено з попереднім фільтром меню без змін цієї задачі; тест залишено без змін. Цільова перевірка меню та production-збірка проходять.
