# Зрозуміле розміщення текстів сторінок і статей

Причина: два незалежні вибори призначення в `/admin/content`, обов’язкові обкладинка й опис для текстових блоків та загальне відображення призначених статей тільки після основного вмісту не дозволяли зручно додати текст над формою оренди.

Зміни:

- Єдине поле «Де опублікувати матеріал» для блогу, новин, благодійності й текстів конкретних сторінок.
- Розміщення на початку/наприкінці сторінки, а для п’яти сторінок співпраці — над формою; новий текст сторінки співпраці за замовчуванням додається над формою.
- Серверне завантаження опублікованих текстів над формами; виключення цих текстів із загального блоку layout.
- Текст сторінки може не мати обкладинки й короткого опису; для окремих статей ці поля залишаються обов’язковими. Категорії приховані для текстів сторінок.
- Збереження помилок без очищення введених даних; кнопка додавання заблокована до завершення початкового завантаження.
- Зворотна сумісність: відсутній `placement` означає попереднє розміщення наприкінці сторінки. Міграція БД не потрібна.

Перевірки: TypeScript; `node scripts/check-menu-content.cjs` із реальними API/auth handlers та підміною репозиторію в пам’яті. Перевірено збереження тексту без обкладинки/опису, HTML усіх п’яти сторінок співпраці з текстом перед формою, виключення чернеток і чужих розміщень, валідацію недопустимих розміщень та збереження старої поведінки статей і меню. Обробники реального редактора перевірено через підміну React hooks: вибір сторінки оренди встановлює розміщення над формою; невдале збереження залишає введений текст; успішне зберігає правильне призначення через API та очищає форму. Робоча БД не змінювалася.

Інструкція для адміністратора: `docs/menu-content.md`. Зміни підготовлені в локальному коді; розгортання на сервері в межах цієї задачі не виконувалось.
