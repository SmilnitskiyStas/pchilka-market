# 160 / 2026-02-26 / fix banner upload to server url instead of base64

## Що зроблено
- Виправлено логіку завантаження зображення банера в адмінці:
  - `components/admin/admin-banners-manager.tsx`
  - замість `FileReader -> data:image/...;base64` тепер використовується серверний upload через `POST /api/admin/images`.
  - для банерів додається `folder=admin/banners`.
- Оновлено валідацію `src` у формі банера:
  - заборонено `data:image/...` у полі шляху;
  - дозволено `/img/...`, `/uploads/...`, `http(s)://...`.
- Додано серверну валідацію в API банерів:
  - `app/api/admin/banners/route.ts`
  - заборонено збереження `data:image/...` у `src`.

## Причина проблеми
- Раніше файл банера зберігався як base64-рядок у `src`.
- Поле `banners.image_url` у MySQL має обмеження `VARCHAR(1024)`, тому base64 обрізався і давав битий `SRC`.

## Перевірка
- `cmd /c npm run typecheck` — успішно.

## Результат
- Нові банери з upload зберігаються як нормальні URL (файли на сервері), а не як base64.
- Механізм збереження банерів захищений від повторного запису base64-даних.

## Що залишилось
- Для вже зламаних старих банерів у БД потрібно перевибрати/перезавантажити зображення в адмінці (їхній старий обрізаний base64 не відновлюється).
