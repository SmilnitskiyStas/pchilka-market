# Персональні запрошення до інженерного Telegram-бота

Ручне введення Telegram ID в адмінпанелі замінено на створення персонального посилання за іменем працівника. Кнопка копіювання й поле для ручного копіювання дозволяють передати запрошення; автоматична відправка іншим людям не виконується. Працівник відкриває посилання та натискає «Почати», бот сам отримує Telegram ID і активує доступ та особисті сповіщення.

Посилання одноразове й діє 7 днів. У таблиці engineering_invites зберігається лише хеш випадкового 256-бітного токена; сам токен повертається тільки при створенні. Прийняття виконується транзакційно з блокуванням рядка та допускається лише в особистому чаті. Повторна доставка активації тому самому активному акаунту безпечна, інший акаунт не може використати запрошення повторно. Чинний користувач не може змінити своє ім’я, використавши чуже запрошення. Видалений доступ не відновлюється старим посиланням.

Додано статуси запрошень та скасування невикористаних посилань. Видалення працівника атомарно вимикає доступ і скасовує його попередні запрошення та невикористані запрошення з тим самим іменем. Раніше додані користувачі зберігають доступ. Додаткова таблиця створюється автоматично; для ручного застосування підготовлено SQL 044.

Перевірки: 10 автоматичних сценаріїв успішні, включно з новими перевірками хешування токена, одноразового використання, закінчення строку дії, скасування, повторної активації після видалення та заборони активації в групі. TypeScript, production build і git diff --check успішні. SQL 044 відповідає схемі, яку створює застосунок. Жива активація через Telegram, розгортання та коміт нових змін не виконувалися.
