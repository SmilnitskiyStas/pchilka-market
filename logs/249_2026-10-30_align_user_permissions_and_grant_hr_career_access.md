# Права модулів і доступ HR до вакансій

Дата: 2026-10-30.

Оновлено admin/users: групи, назви й адреси сторінок відповідають новому меню; дані формуються зі спільної структури навігації. Прапорці отримали зрозумілі aria-label, додано пояснення про повторний вхід, зв’язок запису/видалення з переглядом та системні обмеження.

Додано ресурс career_telegram для окремого доступу до бота вакансій. Відповідність шляхів однакова для сторінки та API. Старі telegram-права продовжують працювати для обох ботів; новий HR-ресурс не надає доступу до тестового бота. GET для editor не повертає токен; PUT/POST системних налаштувань залишаються admin-only.

Через SSH перевірено активного hr_pchilka (id 3, editor). Після приватного резервного копіювання виконано транзакційне додавання career_telegram:read/write з SELECT FOR UPDATE та перевіркою незмінності початкового запису. messages:read/write збережені. Перевірено результат SELECT. Резерв: /srv/pchilka-app/backups/hr-access-20261030-124211. Паролі й секрети не зберігалися в репозиторії.

ВАЖЛИВО: новий ресурс почне діяти після розгортання нового коду та повторного входу hr_pchilka. Збірка, розгортання й перезапуск не виконувалися відповідно до вказівки користувача.

Перевірки: scripts/check-admin-navigation.cjs (42 адреси, повнота груп прав, ізоляція HR, сумісність), scripts/check-career-applications.cjs (реальний API з підписаними тестовими сесіями, vacancy PATCH, read-only відмова, system PUT/POST відмова, виключення тестового бота), TypeScript без incremental, git diff --check. У старому тесті навігації актуалізовано очікуваний список: чинний engineering був відсутній у fixture. Тестові API не звертаються до робочої БД і не надсилають Telegram-повідомлень.
