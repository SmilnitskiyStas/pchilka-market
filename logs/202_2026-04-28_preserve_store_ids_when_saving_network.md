# 202. Preserve store ids when saving network

Дата: 2026-04-28

## Проблема

- Після додавання або збереження магазинів у розділі адмінки `Мережа` користувач inventory міг отримати `users.store_id = NULL`.
- Причина: `replaceStoresInDb()` видаляв усі записи з `stores` через `DELETE FROM stores`, а потім створював їх заново.
- Через зовнішній ключ `users.store_id -> stores.id ON DELETE SET NULL` прив'язка користувача до магазину обнулялась.
- Додатковий ризик: `product_batches.store_id -> stores.id ON DELETE CASCADE` міг видаляти партії при повному видаленні магазинів.

## Зроблено

- Перероблено `replaceStoresInDb()` у `lib/stores-repository.ts`.
- Існуючі магазини тепер оновлюються по стабільному numeric `id`.
- Нові магазини додаються через `INSERT`.
- Магазини, які відсутні в новому списку, видаляються тільки якщо до них не прив'язані користувачі, партії, activity logs або notification logs.
- Якщо магазин має пов'язані записи, API повертає зрозумілу помилку і не ламає прив'язки.
- Додано можливість в адмінці inventory змінити магазин користувача, щоб відновити записи, які вже отримали `store_id = NULL`.
- Для Telegram-сторінки керуючого збережено обмеження: керуючий може редагувати тільки працівників свого магазину.

## Перевірка

- `cmd /c npm run build` - успішно.

## Що зробити для вже пошкодженого користувача

- Відкрити `/admin/inventory`.
- Перейти в розділ `Працівники`.
- Обрати користувача, у якого показано `Магазин не прив’язано`.
- У картці працівника вибрати правильний магазин і натиснути `Зберегти зміни`.
