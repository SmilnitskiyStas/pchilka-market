# Правила лояльності з адмінпанелі замість технічного попередження

Причина підтверджена кодом та публічним API production: для `/loyalty/rules` уже є опублікований текст довжиною 19067 символів із placement=before-content. Шаблон незалежно від цього читав відсутній `public/img/loyalty_programm/program_rules.txt` і показував відвідувачам технічне попередження. У локальній копії цього файлу також немає.

Сторінка тепер завантажує призначені їй опубліковані тексти з БД у власний основний вміст під h1. Правила додані до dedicatedArticlePages, тому спільні блоки layout їх не дублюють; службова назва матеріалу не додається окремим видимим заголовком. Старий TXT читається лише за відсутності опублікованих правил. Якщо обидва джерела відсутні, показується повідомлення «Правила програми лояльності поки що не опубліковані» без файлових шляхів.

API збереження зберігає сумісність із наявним placement=before-content для правил, щоб новий спосіб відображення не заблокував редагування вже створеного контенту. Текст правил не редагувався, нові юридичні умови не створювалися. Публічний production API читався без авторизації; записів у production БД, розгортання та коміту не виконано.

Перевірки: TypeScript і git diff --check успішні. Чотири інтеграційні сценарії scripts/check-loyalty-rules.cjs пройшли: опублікований текст показується один раз без чернеток і читання файлу, старе placement зберігається через API, резервний файл працює без опублікованого контенту, а порожня сторінка не показує технічних шляхів. Перевірки використовують лише репозиторій у пам’яті та підміну читання резервного файлу.
