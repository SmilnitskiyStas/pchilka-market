# Діагностика відмови Telegram Unauthorized

Користувач надав відповідь POST /api/admin/engineering: `{"ok":false,"error":"Telegram: Unauthorized"}`. Вона підтверджує, що Telegram відхиляє використовуваний токен; це окремо від відсутності авторизації адміністратора сайту. Конкретний токен і факт відкликання/помилки копіювання не перевірялися, оскільки у локальній конфігурації його немає. Потрібне введення чинного токена через адмінпанель. DNS публічного домену визначається; це не підтверджує реєстрацію webhook або правильність токена.

Клієнт Telegram зберігає код помилки зовнішнього API й етап методу без включення токена. SetupError розрізняє відхилений токен (telegram_token_unauthorized), токен іншого бота (telegram_wrong_bot), некоректні налаштування та зовнішній збій (telegram_api_error, HTTP 502). Раніше всі відмови підключення позначалися HTTP 400. Для Unauthorized додано українську інструкцію введення чинного токена саме інженерного бота з BotFather; помилка відображається також біля кнопок підключення. Читання/запис токена прибирає випадкові крайові пробіли та перенесення рядків; пробіли пароля пошти не змінюються.

Перевірки: 19 сценаріїв успішні, включно з Unauthorized без наступного setWebhook, розрізненням мережевої помилки, збереженням error_code без розкриття токена й нормалізацією пробілів токена. Живі токени, webhook, доступи та production-конфігурація не змінювалися. Розгортання та коміт не виконувалися. Зміни попередньої задачі про заголовки сторінок залишені в робочій папці.
