## PROJECT PROMPT: Pchilka Web App

### 1. Мета проєкту
- Переробити існуючий сайт `https://pchilka-market.ua/` (WordPress) у новий вебзастосунок.
- Зробити сучасний, адаптивний, швидкий сайт з адмінпанеллю для керування контентом.

### 2. Технологічний стек
- Framework: `Next.js (App Router) + TypeScript`
- UI: `Tailwind CSS`
- Backend/DB/Auth/Storage: `MySql`
- SEO: `Metadata API`, SSR/Server Components, `next/image`, sitemap/robots/canonical

### 3. Дизайн та бренд
- Основні кольори:
- `#62A61D` (зелений)
- `#FFFFFF` (білий)
- Логотип: `public/img/logo.png`
- Банери: `public/img/baners/`
- Вимога: повна адаптивність (mobile/tablet/desktop)

### 4. Scope MVP (поточний етап)
- Робимо архітектуру і базову структуру проєкту.
- Запускаємо головну сторінку як основний публічний екран.
- Підключаємо базовий SEO-контур.
- Готуємо каркас адмінпанелі.
- Каталог товарів у MVP:
- Публічний список товарів: `не входить` у першу ітерацію.
- Дані та структура під товари: `закладаємо` для наступних етапів.

### 5. Функціональні модулі
- Публічна частина:
- Головний банер(и) з переходом на сторінку події/акції.
- Блог на головній сторінці.
- Блок "Як нас знайти": список магазинів, адреси, Google Maps.
- Соціальні мережі.
- Футер.
- PDF-каталог (посилання/блок завантаження або перегляду).
- Акції тижня та додаткові акційні пропозиції.
- Блок про програму лояльності (cashback через мобільний застосунок).
- Адмінпанель (далі, по ітераціях):
- Керування банерами, акціями, блогом.
- SEO-поля (title/description/canonical/open graph) для сторінок.
- Керування товарами (коли модуль каталогу буде увімкнено).

### 6. SEO та індексація
- Використовуємо `generateMetadata` для сторінок.
- Канонічні URL мають генеруватись автоматично.
- Додаємо `sitemap.xml` та `robots.txt`.
- Рендер критичного контенту на сервері.
- Оптимізація зображень через `next/image`.

### 7. Локалізація
- Поточна мова: `українська`.
- Архітектуру під мультимовність закладаємо одразу.
- Додаткові мови будуть визначені пізніше.

### 8. Ролі та доступ
- Поточна роль: `admin`.
- Надалі: додаткові ролі з обмеженими правами (редактор/контент-менеджер тощо).

### 9. База даних (MySQL)
- Фінальна схема БД ще не затверджена.
- На етапі реалізації створюємо таблиці, поля і зв'язки по модулях.
- Усі SQL-скрипти документуємо в `docs/sql`.

### 10. Процес роботи перед стартом задач
- Проаналізувати цей файл і актуалізувати пріоритети.
- Проаналізувати папку `logs`.
- Проаналізувати документацію підключень і БД у `docs/`.
- Після підключення БД робити дослідні запити, документувати структуру і результати.

### 11. Правила ведення документації
- Після завершення будь-якої задачі створювати лог у `logs/`.
- Формат назви: `номер_документу_дата_коротка-назва-дії.md`
- Оновлювати документацію: що зроблено / що залишилось.
- SQL-файли зберігати в `docs/sql/`.
- Формат назви SQL: `номер_документу_коротка-назва-дії.sql`
- Підготувати та підтримувати окремий файл по контенту сайту (наповнення сторінок, тексти, блоки).

### 12. Definition of Done для MVP
- Проєкт запускається локально без критичних помилок.
- Головна сторінка адаптивна і містить узгоджені блоки.
- Базові SEO-метадані та canonical налаштовані.
- Є базовий каркас адмінпанелі з авторизацією admin.
- Створено/оновлено документацію та лог виконаних робіт.

### 13. Питання на уточнення від замовника
Статус уточнень (оновлено):

1. Які саме блоки мають бути на головній у MVP і в якому порядку?
- Статус: `pending`.

- Рішення: контент є в базі даних WordPress; дані будемо або мігрувати, або наповнювати заново.

3. Потрібен блог у MVP як повноцінний модуль чи як статичний блок?
- Рішення: повноцінний модуль блогу.

4. Формат "Як нас знайти": список магазинів + одна мапа, чи окрема мапа на кожен магазин?
- Попереднє рішення: загальна мапа.
- Статус: `pending` (може бути змінено).

5. Чи потрібна форма зворотного зв'язку/заявки в MVP?
- Рішення: так, форма вже готова.

6. Які сторінки обов'язково індексуємо на першому етапі?
- Рішення: спочатку головна сторінка, далі поступове розширення індексації.

7. Які поля SEO потрібні в адмінці в MVP (мінімум: title/description/canonical)?
- Рішення: пріоритет на ключові SEO-поля для коректної індексації.
- Обов'язково реалізувати: `title`, `description`, `canonical`, генерацію `sitemap.xml`, `robots.txt`.
- Додатково: підтримка `.htaccess` (для інфраструктури/хостингу, де це застосовно).

8. Чи потрібна інтеграція аналітики одразу (`GA4`, `GTM`, `Meta Pixel`)?
- Рішення: так.
- Вимога: в адмінпанелі мають бути поля для налаштування/підключення сервісів аналітики.

9. Яка структура URL бажана (приклади slug для сторінок/акцій/блогу)?
- Рішення: `домен/категорія/назва-статті`.
- Вимога: транслітерація slug (наприклад, `привіт` -> `pryvit`).

10. Які дедлайни для MVP (дата першого демо і дата релізу)?
- Демо: перший реліз до `20.02.2026` - відбувся, все добре.
- Реліз: '28.02.2026'

### 14. Критерії "Готово / Не готово" для MVP головної сторінки

#### 14.1 Загальні критерії сторінки
- Готово:
- Сторінка відкривається без критичних помилок у локальному середовищі.
- Є адаптивна верстка для mobile/tablet/desktop.
- Усі блоки зі scope MVP відображаються у погодженому порядку.
- Базові SEO-метадані (`title`, `description`, `canonical`) підключені через `generateMetadata`.
- Налаштовано `sitemap.xml` та `robots.txt`.
- Не готово:
- Падає рендер сторінки або є критичні runtime/build помилки.
- Є злами верстки на основних брейкпоінтах.
- Відсутній хоча б один обов'язковий MVP-блок.
- Немає базового SEO-контуру.

#### 14.2 Головний банер(и)
- Готово:
- Банер(и) відображаються на всіх цільових екранах без зламу.
- Є коректний перехід на сторінку події/акції.
- Зображення оптимізовані через `next/image`.
- Контент банера керований (або підготовлений до керування) з адмінпанелі.
- Не готово:
- Банер не відкривається або не клікабельний.
- Лінк веде на некоректний URL.
- Зображення підключено без оптимізації.

#### 14.3 Блог на головній
- Готово:
- На головній є блок блогу з актуальними публікаціями/прев'ю.
- Є перехід на сторінку публікації або списку блогу.
- Структура передбачає повноцінний модуль блогу (не лише статичний текст).
- Не готово:
- Блок блогу відсутній або статичний без навігації.
- Немає зв'язку з модулем блогу.

#### 14.4 Блок "Як нас знайти"
- Готово:
- Є список магазинів з адресами.
- Підключено карту (поточне рішення: загальна мапа).
- Дані блоку придатні до керування через адмін-процес/адмінку.
- Не готово:
- Немає адрес або карта не відображається.
- Дані неможливо оновлювати без правок коду (без тимчасово погодженого винятку).

#### 14.5 Соціальні мережі
- Готово:
- Відображаються іконки/посилання на актуальні соцмережі бренду.
- Усі посилання валідні та відкриваються коректно.
- Не готово:
- Відсутній блок або посилання биті/ведуть не туди.

#### 14.6 Футер
- Готово:
- Є базовий футер з ключовою інформацією та навігаційними посиланнями.
- Футер коректно відображається на всіх цільових екранах.
- Не готово:
- Футер відсутній або має критичні візуальні/функціональні дефекти.

#### 14.7 PDF-каталог
- Готово:
- Є блок або посилання для перегляду/завантаження PDF-каталогу.
- Файл відкривається або завантажується без помилок.
- Не готово:
- Посилання на PDF відсутнє або не працює.

#### 14.8 Акції тижня та додаткові акції
- Готово:
- Є окремий візуальний блок акцій на головній.
- Для кожної акції є заголовок і перехід на деталі (за наявності сторінки).
- Не готово:
- Блок акцій відсутній або не містить клікабельних елементів.

#### 14.9 Блок програми лояльності
- Готово:
- На головній є блок про cashback/програму лояльності.
- Текст/CTA узгоджені з фактичною пропозицією.
- Не готово:
- Блок відсутній або містить неактуальну інформацію.

#### 14.10 Форма зворотного зв'язку/заявки
- Готово:
- Форма присутня на головній (або в погодженому місці з переходом з головної).
- Валідовано обов'язкові поля.
- Після відправки користувач бачить зрозумілий статус успіху/помилки.
- Не готово:
- Форму неможливо надіслати.
- Немає валідації або немає зворотного повідомлення користувачу.

#### 14.11 Базовий каркас адмінпанелі (для MVP)
- Готово:
- Є авторизація ролі `admin`.
- Є базовий доступ до керування ключовим контентом MVP (мінімум: банери/акції/блог або підготовлений каркас під них).
- Є поля для базового SEO (`title`, `description`, `canonical`) і налаштування аналітики (`GA4`, `GTM`, `Meta Pixel`) згідно вимог.
- Не готово:
- Відсутня авторизація admin.
- Немає каркасу керування MVP-контентом.
- Немає мінімально необхідних SEO/аналітичних налаштувань.
