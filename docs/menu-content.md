# Статті на сторінках меню

В Admin → Контент (`/admin/content`) поле «Сторінка для статті» призначає статтю наявній сторінці меню. Стандартне призначення зберігає попередню поведінку блоків Блог, Новини мережі та Благодійність. Для інших сторінок опубліковані статті відображаються повністю під основним вмістом сторінки, з обкладинкою та Markdown-форматуванням. Посилання попереднього перегляду веде до статті на обраній сторінці.

Призначення зберігається як необов’язкове поле `pagePath` у наявних даних `blog_content_v1` таблиці `site_settings`; зміна схеми БД не потрібна. Старі записи без цього поля залишаються у своїх блоках. Статті з іншим призначенням не дублюються у блозі, новинах або благодійності.

Головне меню на комп’ютері та в мобільній версії приховує інформаційні сторінки без опублікованих статей. Чернетки не вважаються наповненням. Наявні статичні статті блогу, новин і благодійності також враховуються. Порожні групи меню приховуються. Функціональні сторінки (головна, каталог, шок ціна, магазини, контакти, звітність, кар’єра, застосунок, форми співпраці) доступні незалежно від статей. Прямі адреси прихованих сторінок залишаються доступними.

Публічний `/api/site/content` віддає тільки опубліковані призначені статті та список наповнених сторінок. Навігація і статті оновлюються при переходах та поверненні фокусу до вкладки. Публічне читання `/api/admin/blog/content` також виключає чернетки; авторизовані адміністратори бачать усі записи.

Перевірки: `npm run typecheck`, `node scripts/check-menu-content.cjs`. Інтеграційний сценарій підміняє тільки репозиторій БД у процесі тесту й не змінює робочий контент.
