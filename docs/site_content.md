## Сторінка каталогу акцій (`/promotions/catalog`)
- Великий активний PDF-каталог у форматі flipbook.
- Перегляд у форматі "книги" зі сторінками:
  - на ширших екранах відображаються 2 сторінки одночасно;
  - на мобільних екранах відображається 1 сторінка.
- Стрілки по краях "книги" перегортають сторінки.
- Додана анімація перелистування і кешування сусідніх сторінок.
- Попередні каталоги відображаються меншими картками.
- Клік по картці архіву відкриває вибраний каталог у великому перегляді.
- Джерело файлів: `public/pdf/promotions` (усі `.pdf` зчитуються автоматично).
- Кількість сторінок для кожного PDF визначається на сервері (без клієнтських PDF-бібліотек).

## Сторінка "Шок ціна" (`/promotions/shock-price`)
- Відображається адаптивна галерея зображень акцій.
- Джерело файлів: `public/img/shock_price`.
- Зображення зчитуються автоматично (без ручного додавання в код).
- Порядок показу: новіші файли відображаються першими.
- Кожне зображення показується повністю, без обрізання по краях.
- Якщо в кінці галереї лишається 1 картка, сітка автоматично перебудовується, щоб останні 2 рядки були по 2 картки.
- Клік по картці відкриває збільшене фото на цій же сторінці (modal/lightbox) для детального перегляду.

## Хедер
- Глобальний хедер з логотипом і меню відображається на кожній сторінці (через `app/layout.tsx`).
- Випадаючі підменю мають пріоритет відображення над банером (підвищено `z-index`).
- Після кліку по пункту меню/підменю випадаючий список закривається автоматично.

## Адмін-панель (перший етап)
- Доступний маршрут: `/admin` (тимчасово без авторизації, відкритий доступ).
- Додано каркас розділів:
  - `/admin/banners`
  - `/admin/promotions`
  - `/admin/blog`
  - `/admin/own-brand`
  - `/admin/seo`
  - `/admin/integrations`
- У кожному розділі є базовий шаблон форми/полів для наступної інтеграції з БД.
- Для `/admin/banners` реалізовано робочу сторінку:
  - кнопка `Додати новий банер`;
  - модальне вікно додавання банера;
  - список усіх наявних банерів з превʼю (зображення, alt, src, link, статус);
  - у формі є два режими додавання зображення:
    - шлях/URL;
    - завантаження файлу;
  - у формі є вибір сторінки для переходу (зі списку доступних сторінок меню);
  - у формі є планування публікації:
    - дата/час початку;
    - дата/час завершення;
  - для кожного банера доступне редагування через кнопку `Редагувати`;
  - у списку банерів додано фільтрацію:
    - за назвою (пошук);
    - за активністю (активні/неактивні);
    - за періодом публікації (публікується/заплановано/завершено/без періоду);
    - за конкретною датою (пошук банерів, що мають період публікації на обрану дату);
  - випадаючі фільтри стилізовані (кастомне відображення select-полів);
  - локальне збереження нових банерів у `localStorage` (тимчасово до інтеграції з БД).

## Уточнення замовника (2026-02-18)
- Порядок блоків головної сторінки у MVP:
  - поточний варіант залишаємо без змін до окремого погодження.
- Джерело контенту:
  - контент є в наявній БД WordPress;
  - дозволено 2 сценарії: міграція даних або повторне ручне наповнення.
- Блог:
  - у MVP потрібен повноцінний модуль (список + сторінка статті + SEO).
- Блок "Як нас знайти":
  - поточний пріоритет: загальна карта;
  - остаточне рішення ще в узгодженні.
- Форма зворотного зв'язку:
  - реалізована і обов'язкова у MVP.
- Індексація:
  - перший етап: індексуємо головну сторінку;
  - подальше розширення індексації виконується поступово.
- SEO/технічні файли:
  - обов'язково підтримати `title`, `description`, `canonical`;
  - обов'язково підготувати `sitemap.xml` і `robots.txt`;
  - `.htaccess` підтримуємо за потреби інфраструктури.
- Аналітика:
  - потрібна інтеграція в MVP;
  - в адмінпанелі потрібні поля для налаштування `GA4`, `GTM`, `Meta Pixel`.
- URL-структура:
  - формат: `домен/категорія/назва-статті`;
  - slug має формуватись транслітерацією (приклад: `привіт` -> `pryvit`).
- Дедлайн:
  - перший реліз MVP до `2026-02-20`.
