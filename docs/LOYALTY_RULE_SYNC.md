# Локальна синхронізація аналітики правил лояльності

Програма читає дані з POS PostgreSQL і передає їх через захищений API на сайт. Записів до касової бази вона не створює. На сервері дані зберігаються окремо для аналітики правил **836** і **838**.

## Налаштування

Локальний файл `config\loyalty-rule-sync.local.json` містить доступ до POS та ключ API сайту. Він не потрапляє до Git. У цій інсталяції він уже налаштований.

У конфігурації:

- `sync.rules`: правила для передавання, зараз `836` і `838`;
- `lookbackDays`: скільки останніх днів повторно перевіряти. Значення `2` захищає від запізнілих записів і не створює дублікатів;
- `target.url`: адреса сайту. Якщо сервер зміниться — змінюється тільки це поле.

## Ручний запуск

Подвійне натискання на `run-loyalty-rule-sync.cmd` запускає синхронізацію з повідомленням про результат.

```powershell
# певний період
.\run-loyalty-rule-sync.cmd --from 2026-09-01 --to 2026-09-30

# одне правило
.\run-loyalty-rule-sync.cmd --rule 838 --from 2026-10-01 --to 2026-10-08

# лише перевірити читання, без передавання на сайт
.\run-loyalty-rule-sync.cmd --dry-run
```

## Автоматичне оновлення

Для Планувальника завдань Windows використовуйте `run-loyalty-rule-sync-scheduled.cmd`. Він не показує вікно і не очікує натискання клавіші. Рекомендований інтервал — кожні 2 хвилини, лише коли комп’ютер увімкнений та має доступ до касової бази.

Журнал: `logs\loyalty-rule-sync.log`.
