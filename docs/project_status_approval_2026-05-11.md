# Документ Для Погодження Керівництвом

**Дата:** 11 травня 2026 року  
**Тема:** Статус реалізації цифрових проєктів компанії та оцінка виконаної роботи

## 1. Мета документа

Цей документ підготовлено для інформування вищого керівництва щодо поточного стану двох ключових цифрових проєктів:

1. нового вебзастосунку компанії, який готується на заміну чинному сайту;
2. застосунку для додавання, обліку та контролю партій товару з інтеграцією через Telegram.

Окремо в документі відображено:

- поточний рівень готовності кожного напряму;
- бізнес-цінність реалізованого функціоналу;
- перелік робіт, які вже виконані;
- наступні етапи розвитку;
- оцінку особистого внеску у виконання зазначених завдань.

## 2. Загальна інформація про проєкти

### 2.1. Новий вебзастосунок компанії

Новий вебзастосунок створюється як сучасна заміна наявному сайту компанії.  
Його призначення:

- забезпечити публічний доступ для всіх користувачів;
- оновити зовнішній вигляд, структуру та зручність користування;
- створити технічну основу для подальшого розширення функціоналу;
- централізувати адміністрування контенту та службових розділів.

Цей проєкт є важливим як з точки зору іміджу компанії, так і з точки зору технічної модернізації цифрової інфраструктури.

### 2.2. Застосунок для відстеження партій товару

Другий напрям реалізовано як окремий прикладний модуль для внутрішнього користування, який інтегровано в загальний вебпроєкт.  
Його основне призначення:

- додавання товарів та партій до бази даних;
- контроль строків придатності;
- розподіл відповідальності між працівниками;
- взаємодія працівника із системою через Telegram;
- перевірка критичних товарів;
- підготовка до подальшої інтеграції з 1С або CashDesk;
- подальший контроль залишків та руху товару за методом FEFO.

Цей модуль спрямований на зменшення операційних ризиків, покращення контролю залишків та підвищення дисципліни обліку товару в магазинах.

## 3. Поточний статус готовності

### 3.1. Статус нового вебзастосунку

Поточний статус: **проєкт функціонально підготовлений, перебуває на стадії перегляду та погодження.**

На цей момент:

- сформовано новий вебсайт як заміну старому;
- реалізовано основну структуру публічної частини;
- підготовлено адміністративні сторінки та службову архітектуру;
- забезпечено технічну основу для подальшого розвитку.

Разом з тим, частина додаткового функціоналу ще не завершена, оскільки на поточному етапі пріоритет було зміщено на реалізацію критично важливого внутрішнього модуля відстеження партій товару.

Таким чином, вебзастосунок можна оцінювати як такий, що:

- технічно готовий до фінального перегляду;
- проходить етап внутрішнього погодження;
- потребує завершення окремих функціональних блоків у наступних ітераціях.

### 3.2. Статус застосунку для відстеження партій товару

Поточний статус: **проєкт перебуває на стадії тестування, але вже має реалізовану основну бізнес-логіку.**

На цей момент реалізовано:

- структуру товарів і штрихкодів із розподілом даних по окремих таблицях;
- імпорт товарів із файлу;
- логування результатів імпорту;
- підтримку одного товару з кількома штрихкодами;
- пошук товару за назвою або штрихкодом;
- облік партій товару;
- контроль строків придатності;
- призначення відповідальних працівників;
- роботу працівника через Telegram;
- екран перевірки товару з фіксацією результатів;
- журнал перевірок;
- задачі по товарах із ризиком по строках;
- сторінку задач по працівниках;
- перший етап інвентаризації товарів із фіксацією фактичних залишків і збереженням коригувань.

З огляду на це, модуль уже є робочою системою для тестування внутрішніх бізнес-процесів.

## 4. Бізнес-цінність реалізованого функціоналу

### 4.1. Для нового вебсайту

Розробка нового сайту дає компанії такі переваги:

- сучасна та більш керована цифрова платформа;
- покращення якості представлення компанії в публічному просторі;
- зручніша основа для подальших змін, розширень і інтеграцій;
- зменшення залежності від старої структури сайту.

### 4.2. Для системи контролю партій товару

Реалізований модуль дає компанії значно вищий рівень контролю над товаром:

- видно, які саме товари і партії є в обліку;
- можна контролювати строки придатності;
- можна призначати відповідальних працівників;
- можна надсилати задачі на перевірку критичних товарів;
- формується база для точнішого контролю залишків;
- створюється підґрунтя для автоматизованого списання та контролю руху товару.

У подальшому після інтеграції з 1С або CashDesk система дозволить:

- отримувати інформацію про проданий товар;
- зменшувати залишки в системі автоматично;
- працювати за принципом FEFO;
- виділяти критичні позиції;
- направляти працівникам задачі для фізичної перевірки товару;
- точніше розуміти реальні залишки та розбіжності.

## 5. Ключові виконані роботи

У межах реалізації проєктів виконано значний обсяг технічної та прикладної роботи, зокрема:

- підготовлено нову архітектуру вебзастосунку;
- реалізовано публічні та адміністративні сторінки сайту;
- впроваджено inventory-модуль у межах загального проєкту;
- побудовано структуру бази даних для товарів, штрихкодів і партій;
- реалізовано механізм імпорту товарів із файлів;
- впроваджено обробку дублювання штрихкодів і товарів;
- реалізовано пошук товару за назвою та штрихкодом;
- впроваджено призначення відповідального за партію;
- налаштовано Telegram-взаємодію з працівниками;
- реалізовано сторінки перевірки товару, задач і контролю по працівниках;
- реалізовано першу версію модуля інвентаризації товару;
- підготовлено основу для FEFO-контролю;
- підготовлено основу для інтеграції з 1С або CashDesk;
- переведено процес розгортання в більш контрольований формат через GitHub.

## 6. Поточний етап тестування

### 6.1. Вебзастосунок

Вебзастосунок знаходиться на етапі:

- перегляду;
- погодження;
- уточнення фінального обсягу функціоналу.

### 6.2. Модуль відстеження партій товару

Модуль знаходиться на етапі:

- внутрішнього тестування;
- перевірки бізнес-процесів;
- поступового розширення функціоналу;
- підготовки до інтеграції з зовнішніми системами обліку.

## 7. Наступні кроки розвитку

Для завершення та масштабування рішення необхідно виконати такі етапи:

1. завершити погодження нового вебзастосунку;
2. завершити тестування модуля відстеження партій;
3. доопрацювати функціонал інвентаризації;
4. впровадити повноцінні сценарії коригування залишків;
5. реалізувати інтеграцію з 1С або CashDesk;
6. автоматизувати контроль проданого товару;
7. реалізувати повноцінний FEFO-контроль;
8. довести систему до робочого виробничого режиму для магазинів.

## 8. Оцінка виконаної роботи та особистий внесок

У межах цих проєктів було виконано не лише окремі технічні задачі, а й сформовано практично повну прикладну основу для двох важливих цифрових напрямів компанії:

- нового офіційного вебзастосунку;
- внутрішньої системи контролю партій товару.

Фактично виконана робота охоплює:

- проєктування структури рішень;
- реалізацію великого обсягу функціоналу;
- побудову та перебудову бази даних;
- налагодження взаємодії користувачів із системою;
- впровадження Telegram-процесів;
- розробку логіки контролю, перевірки та інвентаризації;
- підготовку основи для інтеграції з обліковими системами.

З огляду на масштаб виконаних робіт, рівень відповідальності та фактичний вплив результату на бізнес-процеси компанії, вважаю доцільним позитивно оцінити обсяг і якість виконаної роботи.

## 9. Висновок

Станом на поточний момент можна констатувати таке:

- новий вебзастосунок компанії фактично підготовлений та перебуває на етапі погодження;
- модуль відстеження партій товару вже працює в тестовому режимі та має значний обсяг реалізованого функціоналу;
- реалізовані рішення формують реальну основу для контролю строків придатності, залишків, відповідальності працівників та майбутнього FEFO-обліку;
- виконана робота має прикладну цінність для операційної діяльності компанії та потребує позитивної управлінської оцінки.
