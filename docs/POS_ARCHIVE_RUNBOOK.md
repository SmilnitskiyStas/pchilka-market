# Архів транзакцій POS

## Що працює

Зовнішня PostgreSQL (`pos.order_client`, `pos.wares_order`, `pos.order_pay`) використовується тільки для читання.
Дані надсилаються порціями через захищений endpoint застосунку і постійно зберігаються в серверній MySQL:

- `pos_archive_orders` — чеки та клієнтський код для RFM;
- `pos_archive_order_items` — товари, кількість, ціни, знижки та повернення;
- `pos_archive_order_payments` — оплати;
- `pos_archive_days` — контроль повноти кожного дня.

Повторний запуск ідемпотентний: складені ключі джерела оновлюються, дублікати не створюються.
Дочірні рядки конкретної порції чека перед повторним записом замінюються актуальними.

## Щоденний режим

На комп'ютері, який бачить приватну адресу PostgreSQL, встановлено Windows Task Scheduler завдання
`Pchilka POS daily archive` на 03:30. За замовчуванням воно забирає день за 7 днів до межі
365-денного очищення. Запас дозволяє безпечно повторити запуск при короткому збої.

Ручний запуск дня:

```powershell
npm run analytics:archive-pos -- --date 2026-07-20
```

Діапазон, найстаріші дні потрібно запускати першими:

```powershell
npm run analytics:archive-pos -- --from 2025-07-22 --to 2025-07-28
```

Перевірка джерела без запису на сервер:

```powershell
npm run analytics:archive-pos -- --date 2026-07-20 --dry-run
```

Лог планового запуску: `logs/pos-archive.log`.

## Конфігурація

Сервер застосунку: `POS_ARCHIVE_INGEST_SECRET`.

Комп'ютер-читач: `MARKETING_SOURCE_DB_*`, `POS_ARCHIVE_API_URL`,
`POS_ARCHIVE_INGEST_SECRET`, `POS_ARCHIVE_SOURCE_RETENTION_DAYS=365`,
`POS_ARCHIVE_SAFETY_DAYS=7`. Локальний runner також уміє читати наявний файл
`docs/підключення до бази.txt` і секрет із локального `.env.docker`.

## Контроль диска

Тестовий день 2026-07-20 займає приблизно 166 МБ у MySQL. На момент запуску сервер мав близько
15 ГБ вільного місця, тому поточного диска недостатньо для необмеженого повного архіву.
До заповнення диска потрібно збільшити том або додати стиснений cold-storage. Щоденний контроль
має стежити за вільним місцем і статусами `pos_archive_days`.
